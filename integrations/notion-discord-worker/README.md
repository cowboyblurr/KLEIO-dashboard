# KLEIO Notion → Discord Updates

This Cloudflare Worker turns meaningful KLEIO Notion activity into compact Discord updates without depending on the main KLEIO web deployment.

## What it forwards

Subscribe the Notion connection to:

- `page.content_updated`
- `page.properties_updated`
- `page.created`

For each supported event the Worker:

1. verifies the Notion webhook signature after setup;
2. fetches the current Notion page;
3. fetches up to four changed blocks for content updates;
4. creates a short deterministic change summary;
5. posts a Discord embed with the page title, what changed, timestamp, and direct Notion link.

No AI model or extra prompt cost is required for this first version.

## Runtime secrets

Never commit these values:

- `NOTION_API_TOKEN` — token for a Notion internal integration with read access to the KLEIO pages that should produce notifications.
- `DISCORD_WEBHOOK_URL` — incoming webhook URL for the KLEIO Discord updates channel.
- `NOTION_VERIFICATION_TOKEN` — one-time verification token generated by Notion when the webhook subscription is created. Add this after the first subscription handshake.

The repository-level `.gitignore` already ignores `.env*` files.

## Deploy

From this directory:

```bash
npx wrangler@latest deploy
```

The Worker name is `kleio-notion-discord`. The public Notion webhook endpoint is:

```text
https://<your-workers-subdomain>/webhooks/notion
```

The health endpoint is:

```text
https://<your-workers-subdomain>/health
```

The health response only reports whether required secrets are configured; it never returns secret values.

### Configure Cloudflare secrets

Use Cloudflare Workers → **Settings → Variables and Secrets**, or Wrangler:

```bash
npx wrangler@latest secret put NOTION_API_TOKEN
npx wrangler@latest secret put DISCORD_WEBHOOK_URL
```

After Notion sends its verification request, add:

```bash
npx wrangler@latest secret put NOTION_VERIFICATION_TOKEN
```

## Create the Notion subscription

1. Create or select the KLEIO Notion connection/integration.
2. Give the connection read access to the KLEIO root page and any child areas that should trigger Discord updates.
3. In the connection settings open **Webhooks** → **Create a subscription**.
4. Enter the Worker's `/webhooks/notion` URL.
5. Subscribe to `page.content_updated`, `page.properties_updated`, and `page.created`.
6. Keep Worker logs open (`npx wrangler@latest tail`). Notion sends a one-time `verification_token`; the Worker logs it as a structured `notion_webhook_verification` event.
7. Paste that token into Notion's verification dialog.
8. Store the same value as the Cloudflare secret `NOTION_VERIFICATION_TOKEN`.

Once that secret is present, normal webhook deliveries must pass Notion HMAC-SHA256 signature verification before any Notion or Discord request is made.

## Create the Discord webhook

In the target Discord channel:

1. Edit Channel → Integrations → Webhooks.
2. Create a webhook named `KLEIO Updates`.
3. Copy the webhook URL.
4. Store it as the Cloudflare secret `DISCORD_WEBHOOK_URL`.

Do not put the Discord webhook URL in source code, issues, commit messages, screenshots, or public documentation. Anyone with the URL can post to that channel.

## Test

After the Notion subscription is active:

1. edit text in an accessible KLEIO Notion page;
2. wait for Notion's aggregated content-update delivery;
3. confirm Discord receives a `KLEIO Updates` embed containing the page title, changed text, and direct Notion link.

Notion intentionally batches frequent `page.content_updated` events, so normal content edits can arrive after a short delay rather than on every keystroke.

## Failure behavior

- invalid webhook signatures return `401`;
- missing runtime secrets return `503`;
- Notion or Discord delivery failures return `500`, allowing Notion to retry according to its webhook delivery policy;
- deleted/removed blocks are treated as legitimate changes rather than fatal errors;
- Discord mentions are disabled and common mention syntax is sanitized.
